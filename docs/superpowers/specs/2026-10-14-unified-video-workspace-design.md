# Unified Video Workspace — แบบระบบสำหรับตรวจทาน

สถานะ: ร่างจากความต้องการของผู้ใช้ ยังไม่ใช่การอนุมัติให้เริ่มพัฒนา

## เป้าหมาย

สร้างคลิปขายสินค้าแบบผสมฟุตเทจจริงกับกราฟิกเล่าเรื่องในหน้าเดียว ตั้งแต่เพิ่มรูป/คลิป เรียงฉาก เขียนบท เลือกเสียง แก้คำอ่าน ดูพรีวิว จนส่งออก ไม่ต้องเรนเดอร์จาก Studio แล้วนำวิดีโอกลับไปใส่สตอรี่บอร์ด

ผู้ใช้เลือกแนวผสม และขอให้เห็นเสียงหญิง/ชาย ปรับภาษาบทตามผู้พูด ตรวจคำที่อาจอ่านผิด และกำหนด dodolove → ดูดูเลิฟ ได้ ข้อเสนอเพิ่มเติมในเอกสารนี้เป็นรายละเอียดออกแบบที่ให้ตรวจทาน

## สิ่งที่พบในระบบเดิม

- `/` ใช้ ProductRecord/StoryboardPlan; `/studio` ใช้ StudioProject คนละ state และคนละ composition ไม่มีสะพานส่งงานอัตโนมัติ
- Studio รับวิดีโอเท่านั้น ส่วนหน้าหลักเน้นรูปภาพ
- `ScriptStoryboard.tsx` แยก voiceType กับ geminiVoice จึงเสี่ยงให้ป้ายกับเสียงจริงไม่ตรงกัน
- มี `speechText.ts`, `/api/pronunciation-map` และ UI แก้คำอ่านอยู่แล้ว แต่ใช้พจนานุกรมกลางทั้งระบบ
- `tts.ts` มี fallback เปลี่ยนคำภาษาอังกฤษเป็น “ตัวนี้” และเปลี่ยนเสียงหญิงเป็นชาย ซึ่งขัดกับการควบคุมเสียงที่ผู้ใช้ต้องการ
- บทสร้างผ่าน `generate-script` ยังไม่ส่งตัวเลือกผู้พูดเข้า ScriptGenerationParams

## หน้าทำงานเดียว

ใช้ `/studio` เป็นหน้าสร้างงานหลัก และให้หน้าหลักพาเข้าหน้านี้เมื่อความสามารถครบ เส้นทางเดิมยังเปิดงานเก่าได้

Desktop: แถบข้อมูลสินค้า/สื่อทางซ้าย พื้นที่เรียงฉากและแก้บทตรงกลาง พรีวิวแนวตั้งติดด้านขวา ส่วนเสียงและคำอ่านเปิดในพื้นที่แก้ไขเดียวกัน ไม่พาออกอีกหน้า Mobile: สื่อ → รายการฉาก → รายละเอียดฉาก → พรีวิว แบบหนึ่งคอลัมน์พร้อมปุ่มเล่นพรีวิวที่เข้าถึงง่าย

แต่ละฉากแสดง thumbnail ประเภทสื่อ ระยะเวลา บทพูด และสถานะเสียง กดเลือกฉากเพื่อแก้ช่วงคลิป/ระยะเวลารูป ข้อความบนจอ ซับ และกราฟิก ลากเรียงได้ พร้อมปุ่มขึ้น/ลงสำหรับคีย์บอร์ดและมือถือ

เส้นทางหลัก: เพิ่มข้อมูลสินค้าและสื่อ → สร้างร่างฉาก → ตรวจ/แก้ฉากและบท → เลือกเสียงและตรวจคำอ่าน → สร้างเสียง → พรีวิว → ส่งออก การสร้างร่างใหม่เป็นข้อเสนอให้ยอมรับ ไม่ทับงานแก้เองทันที

## ข้อมูลและการย้ายงาน

ใช้ WorkspaceProject schemaVersion 2 เป็นข้อมูลกลาง; ฉากอ้าง assetId และเก็บบทเป็นรายฉาก บทเต็มเป็นค่าที่ประกอบจากฉาก ไม่เก็บสำเนาที่แก้แล้วไม่ตรงกัน

รองรับ JPEG/PNG/WebP และ MP4/MOV/WebM สูงสุด 20 สื่อต่อโปรเจกต์ ภาพไม่เกิน 20 MB/40 ล้านพิกเซล วิดีโอไม่เกิน 200 MB/10 นาที สูงสุด 150 ฉากและ 300 วินาทีรวม 30 fps ส่งออก 1080×1920

แปลง StudioProject เดิมเป็นฉากวิดีโอโดยคง trim/crop/ซับ แปลง ProductRecord เป็นฉาก hook/body/CTA โดยคงลำดับและบท ไม่เปลี่ยนไฟล์เก่าทับ ถ้าเสียงเดิมมีเพียงไฟล์รวม ให้แนบเป็นเสียงเดิมแบบล็อกและแจ้งให้สร้างเสียงรายฉากเมื่อแก้บท ไม่เดาเวลาแยกเสียงเอง ข้อมูลที่แปลงไม่ได้ต้องแจ้งรายการ ไม่ทิ้งเงียบ ๆ

## กราฟิกและความยาวฉาก

รุ่นแรกมี 3 layout: footage-focus (ฟุตเทจเต็มเฟรมและคำเน้น), product-callout (รูป/คลิปพร้อมจุดขาย), offer-close (สินค้า/ราคา/CTA) ใช้ font สี และการเคลื่อนไหวชุดเดียวกัน ตัวละครเป็นตัวเลือกเสริมภายหลัง ไม่บังคับทับสินค้า

เสียงพากย์จริงกำหนดความยาวขั้นต่ำของฉาก; เพิ่มเวลาเผื่อจบเสียง 0.2 วินาที ถ้ารูปสั้นให้ยืดภาพ ถ้าช่วงคลิปสั้นให้แจ้งก่อนใช้ freeze-last-frame ผู้ใช้เลือกยืดช่วงคลิป ย่อบท หรือยอมรับการค้างภาพได้ ห้ามเร่งเสียงหรือวนคลิปเงียบ ๆ

เสียงต้นฉบับเลือกรายฉาก: original / narration / mix ค่าเริ่มต้น narration เมื่อมีเสียงพากย์; mix ลดเสียงต้นฉบับ 18 dB ระหว่างมีบทพากย์ ไม่มีเพลงอัตโนมัติในรุ่นแรก

## เสียงและภาษาบท

รวม voiceId/provider/providerVoiceId/ป้ายผู้พูดไว้ใน VoiceDefinition เดียว UI แสดง “หญิง / ชาย / ไม่ระบุ” ชื่อเสียง ลักษณะเสียง ปุ่มลองฟัง และสถานะพร้อมใช้งาน แยกสไตล์การพูด เช่น สุภาพ/เป็นกันเอง ออกจากประเภทเสียง

ตรวจรายการเสียงกับเอกสารผู้ให้บริการและฟังตัวอย่างก่อนติดป้ายจริง ห้ามเดาเพศจากชื่อเสียง โคลนหรือเสียงที่ไม่ทราบให้แสดงไม่ระบุและกำหนดรูปแบบภาษาแยกได้

รูปแบบภาษาเป็น female-polite / male-polite / neutral โดยค่าเริ่มต้นสัมพันธ์กับเสียงที่เลือก แต่ปรับแยกได้ เมื่อเปลี่ยนเสียง เสนอข้อความปรับใหม่รายฉากและแสดงก่อน/หลัง ผู้ใช้ยอมรับหรือย้อนกลับได้ บทที่สร้างใหม่ใช้รูปแบบที่เลือกทันที

ปรับสรรพนามและคำลงท้ายตามบริบท เช่น “ครับ”, “ค่ะ”, “คะ” ไม่เปลี่ยนคำกริยาทุกคำหรือใช้ replace ทั้งบท ต้องคงชื่อแบรนด์ ราคา จุดขาย และคำพูดอ้างอิง; neutral ไม่บังคับสรรพนามหรือคำลงท้ายตามเพศ

หากเสียงล้มเหลว ให้ retry เสียงเดิมหนึ่งครั้ง แล้วแสดงข้อผิดพลาด/ตัวเลือกเสียงอื่น ห้ามเปลี่ยนหญิงเป็นชายหรือแทนแบรนด์ด้วย “ตัวนี้” อัตโนมัติ

## ตรวจและแก้คำอ่าน

แยก displayText ที่ใช้ในบท/ซับ/กราฟิกออกจาก textForSpeech ที่ใช้สร้างเสียง ตัวอย่าง displayText “dodolove” และ textForSpeech “ดูดูเลิฟ” ผู้ใช้เพิ่มคู่คำได้เอง แม้เป็นคำไทย

พจนานุกรมเฉพาะโปรเจกต์มีสิทธิ์เหนือค่ากลางเดิม; เพิ่ม/แก้/ลบได้ พร้อมช่องลองฟังทั้งคำและประโยค สแกนชื่อสินค้า แบรนด์ ตัวเลข หน่วย คำอังกฤษ และคำที่ผู้ใช้ทำเครื่องหมาย แสดงว่า “ควรตรวจ” ไม่อ้างว่าระบบรู้คำอ่านที่ถูกแน่นอน

จับคู่ไม่สนตัวพิมพ์ใหญ่เล็ก ใช้คำยาวก่อนคำสั้น ไม่แทนบางส่วนของแบรนด์อื่น และไม่แทนซ้ำผลลัพธ์ที่แทนไปแล้ว กฎรองรับการระบุวลีเต็มสำหรับคำไทย; การแก้คำอ่านไม่เปลี่ยนชื่อสินค้าบนจอ

เปลี่ยนบท/คำอ่าน/เสียง/ความเร็ว/สไตล์แล้วเสียงและซับที่เกี่ยวข้องต้องเป็น stale; render ถูกปิดจนสร้างใหม่หรือย้อนกลับ ใช้ revision/hash ปฏิเสธผล async เก่าที่กลับมาหลังผู้ใช้แก้ข้อมูล

## ซับและพรีวิว

เก็บ token ที่เชื่อม displayText ↔ textForSpeech เพื่อให้ซับแสดง dodolove แม้เวลาเสียงอิง ดูดูเลิฟ ใช้ word timing จากผู้ให้บริการเมื่อมี หรือ alignment ของเสียงจริง หากจับเวลาไม่มั่นใจให้ใช้ซับระดับวลีและแจ้งให้ตรวจ ไม่สร้างจังหวะคำปลอม

พรีวิวและ export ใช้ timeline resolver/composition เดียวกัน ซับเลือกเรียบหรือเน้นคำ ส่งออก MP4 และ SRT; ความคลาดเคลื่อนด้านภาพ/ซับเป้าหมายไม่เกิน 1 เฟรมสำหรับเวลาที่ได้รับการยืนยันแล้ว

## ข้อจำกัดร่วม

- Next.js/React เดิม, Tailwind 4, daisyUI 5 รุ่นล่าสุดที่เข้ากันได้ ณ วันพัฒนา, Lucide; ใช้ semantic theme และรองรับไทย
- Dark mode เป็นหลัก; ตรวจ 390, 768, 1440 px; ไม่มี CSS ระบบใหม่ขนาดใหญ่
- คงงานเก่าและระบบบันทึก/กู้คืน; ห้ามเก็บ API key ในโปรเจกต์หรือ browser
- ตรวจและพัฒนาในแชตนี้เท่านั้น ไม่ใช้ subagent
- งานนี้วางแผนก่อน ยังไม่แก้โค้ดผลิตภัณฑ์

## เกณฑ์ยอมรับ

โปรเจกต์ตัวอย่างมีรูป 2 รูปและคลิป 2 คลิป; เรียงใหม่ ตัดคลิป แก้บท เลือกเสียงหญิง/ชาย และตั้ง dodolove → ดูดูเลิฟ ได้ในหน้าเดียว บันทึกแล้วโหลดกลับครบ ส่งออกได้โดยไม่ต้องดาวน์โหลดแล้วอัปโหลดข้ามหน้า

ฟังไฟล์เสียงจริงยืนยันตัวเลือกและคำอ่าน; ซับยังแสดงแบรนด์เดิม การเปลี่ยนคำอ่านสร้างเสียงใหม่เฉพาะฉากที่กระทบ การเปลี่ยนผู้พูดไม่ทับบทแก้เองโดยไม่แสดง diff งานเก่ายังเปิดได้ และ export ตรงพรีวิว
